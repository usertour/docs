---
title: "setScrollPadding()"
description: "Keep room clear at the page's edges when Usertour scrolls a tooltip's target into view"
---

When a tooltip points to an element outside the viewport, Usertour scrolls that element into view. If your app has a fixed header or a fixed bottom bar, the element can end up underneath it. `setScrollPadding()` tells Usertour how many pixels to keep clear at each edge of the page, so the element lands in the part the user can actually see.

## Parameters

<ParamField path="scrollPadding" type="object | null" required>
  The pixels to keep clear at each edge. Every side is optional and defaults to
  `0`. Pass `null` to clear the padding.

  <Expandable title="properties">
    <ParamField path="top" type="number">
      Pixels to keep clear at the top of the page, e.g. the height of a fixed header.
    </ParamField>
    <ParamField path="right" type="number">
      Pixels to keep clear at the right edge.
    </ParamField>
    <ParamField path="bottom" type="number">
      Pixels to keep clear at the bottom, e.g. the height of a fixed bottom bar.
    </ParamField>
    <ParamField path="left" type="number">
      Pixels to keep clear at the left edge, e.g. the width of a fixed sidebar.
    </ParamField>
  </Expandable>
</ParamField>

## Examples

### Keep a fixed header clear

```javascript
// The app's header is fixed at the top and 64px high
usertour.setScrollPadding({ top: 64 });
```

### A fixed header and a fixed bottom bar

```javascript
usertour.setScrollPadding({ top: 64, bottom: 56 });
```

### Clear the padding

```javascript
usertour.setScrollPadding(null);
```

## How the default scroll works

- A target that fits in the visible part of the page (the viewport minus the padding) is centered in it.
- A target taller than that, such as a long table, is scrolled in by its top, so the user starts at the beginning of it rather than in the middle.
- The padding applies to the page's own scrolling. An element inside a scrolling container or an iframe is still scrolled into view within that container as usual.

## Notes

- You can call it before `usertour.init()`, or before the script has loaded; the call is applied when the SDK loads. Queuing it before load needs the current installation snippet or the `usertour.js` npm package v0.0.28 or newer; an older snippet drops that early call with a warning, so call it again after the SDK has loaded or update the snippet.
- When a [`setCustomScrollIntoView()`](/developers/usertourjs-reference/advanced/set-custom-scroll-into-view) callback is set, your callback does the scrolling and the padding is not used.
- Needs Usertour.js newer than v0.9.9. Usertour Cloud always serves the newest version; self-hosted, upgrade your server. An older version ignores the call and logs a warning.
